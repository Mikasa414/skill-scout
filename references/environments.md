# 环境与检索

## 已有能力

先看当前会话技能清单与可调用工具，识别插件提供的能力，不需要扫描整个插件缓存。再检查用户级技能目录、项目技能目录和适用的项目指令。当前官方文档列出用户级 ~/.agents/skills/ 和项目级 .agents/skills/；部分环境（包括本项目的原始安装环境）使用 ~/.codex/skills/，以实际发现位置为准，避免重复安装。路径以当前会话与本地事实为准，不把其他宿主目录当作 Codex 已安装位置。

## 外部检索

- 注册表可尝试 npx skills find "关键词"。先检查 node/npx；npx 可能下载并执行工具，按当前授权判断，不为纯查询默默安装依赖。也可网页检索。
- GitHub 可用 gh search repos 或网页/API。仓库搜索不等于找到具体技能，需要定位实际 SKILL.md。
- 仓库 API：https://api.github.com/search/repositories?q=<编码后的关键词>。文件 API：https://api.github.com/repos/{owner}/{repo}/contents/{path}。查仓库元数据确认默认分支，不假定为 main。
- 官方或可信来源优先，但仍检查内容；星数仅是弱信号。提供具体来源链接，不以“市场技能，无公开链接”冒充可核实候选。
- 无结果、限流或工具不可用时换检索方式，保留已核实结果并说明限制，不编造候选、不反复刷请求。

## 安装与更新

明确安装后，先检查适用的已安装安装工具或技能；没有合适方式时浅克隆到工作区 work/ 下的唯一临时目录，只复制目标技能和必要资源。Windows 使用原生路径与 PowerShell 文件操作，不照搬 /tmp/x。

安装前检查目标是否存在。明确更新时先备份到技能目录外，避免重复发现；新候选不得静默覆盖同名目录。保留相对路径，检查依赖与引用，使用适用验证器。

区分“文件已安装”与“会话已加载”：报告实际位置，未重新发现时可建议新聊天验证，不保证热加载。

卸载技能目录不一定撤销脚本生成文件、依赖或外部操作，不承诺“删除目录即无残留”。
